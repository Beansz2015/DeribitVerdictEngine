# Fable 5 Engine Audit Report — 2026-06-10

One-off, read-only adversarial audit per `docs/fable5-engine-audit-brief.md`. No source files were modified. Build verified clean (`dotnet build DeribitVerdictEngine.sln`, exit 0). Dynamic verification was done with a throwaway harness at `verify/ordercheck/` (gitignored, links the real shipped `.vb` sources via `<Compile Include>` — zero copies, zero edits; re-run with `dotnet run` from that directory).

## 0. Summary

- **Files read in full:** 21 (all `Core/Indicators_*`, all `Core/ScoringEngine_*`, `EngineSettings`, `SettingsLoader`, `DeribitClient`, `DynamicNorms`, `AnalysisLogger`, `OiSnapshot`, `AutoRunTimer`, `MainForm_Analysis`, `MainForm_AutoRun`, `settings.json`, `AutoTweakerCore`, `TweakerState`, `SettingsDiffApplier`, `ForwardWindowJoiner`, `FailureRateMatrix`, `DeribitOhlcFetcher`). Targeted greps/slices: `LivePerformanceTracker`, `OhlcCache`, `MainForm_Render_Header` (Kelly call site only). See §7 for what was not read.
- **Findings:** 7 confirmed-by-running, 6 confirmed-by-reading (airtight), 6 suspected, ~14 low/style (grouped). **New-function ideas: 7.**
- **Headline:** (1) The engine's trade-flow indicators disagree about trade-list ordering: Deribit returns trades **newest-first** (`sorting=desc`) and nothing reverses them, so **CVD slope and MicroCVD accel/decel are chronologically inverted** — confirmed by running the shipped functions on synthetic data — while TFI is only correct *because* of that same ordering. Three scoring layers, the MOMENTUM_FADING tag, and hold/exit guidance consume the inverted values. (2) `DynamicNorms` computes its volume baseline from the **oldest** 100 of 250 candles (confirmed by running), so volume thresholds adapt to conditions 2.5–4 h stale. (3) The MTF hard veto is evaluated against a pre-scoring direction proposal, not the verdict the engine actually emits — it can both wrongly block and wrongly pass. Everything else is second-order to those three.
- **Calibration warning for triage:** all thresholds touched by v14–v22 sweeps were tuned on logged data that *includes* the CVD/MicroCVD inversion and the stale volume window. Fixing C1/C2/H1 changes the meaning of the `CVDSlope`, `MicroCVDSignal/Early/Late`, and `VolumeRatio`-vs-threshold columns — historical CSV rows will not be comparable, and the related WATCHING items (CVD slope_min, MicroCVD accel, session multipliers) need re-baselining after the fix.

### Prose: the trade-ordering finding (C1/C2/C3)

`DeribitClient.GetRecentTradesAsync` requests `sorting=desc` (`DeribitClient.vb:256`); `recentTrades(0)` is the newest trade (the header's "LAST TRANSACTED PRICE" relies on this). The list flows unreversed into `CalcCVD`, `CalcTFI`, `CalcMicroCVD` (`MainForm_Analysis.vb:294-313`). All three functions index "early/late" from the list head. Result, demonstrated by running the shipped binaries on synthetic fixtures (`verify/ordercheck`):

```
[1] CalcCVD   desc input, truth=RISING  → cvdSlope=FALLING   (INVERTED; asc input → RISING)
[2] MicroCVD  desc input, truth=BULL_ACCEL → BULL_DECEL      (INVERTED; asc input → BULL_ACCEL)
[3] CalcTFI   desc input, truth=BUY PRESSURE → BUY PRESSURE  (correct BECAUSE of desc)
```

Severity justification: `CVDSlope` and `MicroCVDSignal` enter Step 2 voting, Pass 2b (OI×CVD gate direction), Pass 2c (TRENDING alignment), MOMENTUM_FADING tagging, and CalcHoldStatus exit logic. The inversion is not a constant flip of the verdict — net `CVDValue` still gates signs — but every within-window momentum-shift read (the stated purpose of both indicators) is backwards. Note for triage: because the engine was calibrated with these semantics in place, a fix is a **behaviour change requiring recalibration**, not a pure bugfix.

## 3. Resilience / concurrency / portability observations

**Host-agnostic grep (brief §4.6): CLEAN.** `analysis/` contains exactly one WinForms reference — `AnalysisReportForm.vb`, the documented thin-viewer exception. `tools/AutoTweaker/*.vb` has zero `System.Windows.Forms` / `Control.Invoke` / `MainForm` references (only header comments asserting the constraint). `AutoTweaker.csproj` is a separate net8.0 console project.

**Concurrency (brief §4.3): clean overall.**
- The `Task.WhenAll` fan-out only *reads*; all shared state (`_oiHistory`, `_fundingHistory`, `_ofiHistory`, MTF cache, `_prevRegime`) is mutated in post-await continuations on the UI SynchronizationContext — single-threaded by construction.
- Auto-run re-entrancy is properly guarded: `WinFormsAutoRunTimer.OnTick` marshals via `Control.Invoke`, `RunAutoAnalysis` checks `btnAnalyze.Enabled`, and the handler disables the button synchronously before its first await. Overlapping runs are skipped, not queued.
- The one `async void` (`btnAnalyze_Click`) wraps everything in Try/Catch — acceptable event-handler pattern, no unobserved-exception path found.
- `SettingsLoader` lock usage is correct for the reference swap. One soft spot: UI code mutates the *live* `SettingsLoader.Current` instance in place before `Save` (e.g. `StartAutoRun`), relying on everything running on the UI thread. True today; becomes a real race in the CLI port where a timer loop and a settings write can interleave. Worth a convention note in the port spec.
- 15m TTL cache: no expiry/refresh race (single thread); stale-keep on fetch failure works as documented.

**API resilience (brief §4.4): solid, two soft spots.**
- `HttpClient` is a single static reused instance (no socket exhaustion). Timeout set once at static ctor — documented. No `PooledConnectionLifetime`, so a very long-lived process won't pick up DNS/edge changes until a connection naturally dies — LOW.
- `ExecuteWithRetry` semantics check out: 5xx/timeout retried once, 4xx and JSON-rot hard-fail to `Nothing`, JSON-RPC errors inside HTTP 200 land in the generic catch → `Nothing`. The skip-gate in `RunAnalysisAsync` (`Count < 50` / `< 30` / null checks) correctly catches empty-but-not-null responses before any `.Last()` — the obvious empty-list crash is *not* reachable. 15m-failure-keeps-stale-cache behaves as documented.
- Soft spot 1: retry/skip events are `Console.WriteLine`-only — invisible in a WinForms session (see suggestion S7 context). Skip count is surfaced, reasons only for the last skip.
- Soft spot 2: no staleness check on candle data. If Deribit serves a stale-but-valid chart response, `GetSessionCandles` can find zero in-session candles and silently fall back to **the full 250-candle list** as the "session" (`Indicators_Volatility.vb:31`), with `VWAPSessionCandles = 250` defeating the warmup gate. A last-bar-age guard would convert this to a clean skip (suggestion S6).
- `AnalysisOutputDump`/`AnalysisLogger`/`FailureRateMatrix` writers swallow all I/O exceptions by design (logging must not kill the pipeline) — fine, but combined with M4 it means corruption would also be silent.

**Auto-tweaker pipeline:** state writes are atomic (`TweakerState.Save` tmp+Replace — the cleanup-pass fix landed correctly). `RoundHistory` is capped at 1000; `PickedCellHistory` is **uncapped** and grows forever in state.json — LOW. `SuccessfulRoundsForCurrentStreak` takes the last *N entries* then filters by outcome, so SKIPPED_* entries interleaved in a streak shorten the conditions window silently — LOW. `proposed_diffs/` paths are CWD-relative — LOW.

## 5. New-function / capability suggestions (ranked best-first)

1. **`NormalizeTrades` — canonical trade-stream ordering at the fetch boundary.**
   Purpose: kill the C1/C2/C3 class permanently. Signature: `DeribitClient.GetRecentTradesAsync` returns chronological-ascending; add `Public Shared Function LastN(trades As List(Of TradeRecord), n As Integer) As List(Of TradeRecord)` for window selection (TFI/MicroCVD take from the end). Location: `DeribitClient.vb` + call-site updates in the three indicators. Value/effort: fixes two CRITICALs and removes a whole bug class for ~30 lines; the harness in `verify/ordercheck` already encodes the acceptance fixtures. **Profile check:** pure correctness for preferred indicators (CVD/MicroCVD/TFI); no rejected pattern. *Must ship with a calibration note: CSV `CVDSlope`/`MicroCVD*` columns change meaning on fix date.*

2. **Direction-aware MTF gate check in Step 4b.**
   Purpose: enforce the hard-veto invariant against the actual verdict direction (H2). Signature: `CalcMTFGate` already takes `proposedDirection` — compute `gatePassLong`/`gatePassShort` once per run (pure function on cached 15m) and store both on `IndicatorResults`; Step 4b consults the flag matching the dominant side. Location: `MainForm_Analysis.vb` + `ScoringEngine_Calculate_Verdict.vb`.
